# WWS Site Audit — 2026-06-11T1817Z

**Mode:** propose-only (no site/code edits made). First baseline run.

## Executive summary
The site is **functional, secure, and on-message** — admin/portal endpoints gate correctly (403/401), the hero/problem now lead with the emergency angle, and the guides + portal are live. No P0/P1 *breakage*. The biggest wins are **organic-traffic levers that are currently missing**: zero structured data, meta descriptions that are stale or contain raw HTML, and a runtime Tailwind CDN that drags Core Web Vitals. Fixing those three is the highest-leverage work for the stated goal (more traffic + conversions).

## Findings

| Sev | Area | Where | Issue | Recommended fix |
|---|---|---|---|---|
| **P1** | SEO | All pages (landing, guides, portal) | **No structured data (JSON-LD) anywhere** — `application/ld+json` not present. Missing the single biggest organic lever. | Add `LocalBusiness` (landing: name, CGC059211, phone, areaServed Miami-Dade/Broward/Palm Beach, geo), `FAQPage` (the FAQ section), and `Article` + `BreadcrumbList` on each guide. Inject via `_wws_blog_builder.py` HEAD + landing `<head>`. |
| **P1** | SEO | Guide pages — `_wws_blog_builder.py` HEAD `meta=` | **Meta descriptions contain raw HTML and overflow.** e.g. `/guides/osha-penalties` description = `…run up to roughly <strong>$1…` (literal `<strong>` tags), and it's the full `why` paragraph (>300 chars). Google truncates ~155 and strips tags = ugly, low-CTR snippets. | In the generator, derive meta from a plain-text field: strip tags (`re.sub('<[^>]+>','')`) and truncate to ~155 chars. Add a dedicated short `meta` per guide rather than reusing `why`. |
| **P2** | Performance / SEO | Landing + all pages | **Tailwind loaded via `cdn.tailwindcss.com`** (dev CDN) — compiles CSS in-browser at runtime; large JS, render cost, hurts LCP/TBT (a Core Web Vitals ranking signal). Landing HTML alone is ~79 KB before the CDN JS. | Build a purged static `wws.css` (Tailwind CLI) and link it instead of the CDN script. Removes the runtime compile + most of the JS weight. |
| **P2** | SEO / Messaging | `wwslgc/index.html` `<head>` (meta description + `og:description`) | **Stale, citation-only framing.** Meta = "Got an OSHA Subpart D citation… certifies it and fixes it"; `og:description` = "One accountable team… under one contract." Neither reflects the new *"you may already be exposed"* positioning, and both miss the not-yet-cited search audience. | Rewrite both to lead with exposure/inspection-risk and include "walking-working surfaces inspection / compliance South Florida" intent keywords. Mirror the new hero. |
| **P3** | Conversion / IA | `wwslgc/index.html` Problem section | The two new emergency guides aren't surfaced on the landing page (`is-my-building-exposed` not linked anywhere on `/`). The self-check is a strong top-of-funnel hook. | Add a "Not sure? Take the 2-minute self-check →" link to `/guides/is-my-building-exposed` in the Problem section (next to the penalties link). |
| **P3** | SEO | Guide pages | Verify each guide sets a unique `og:image`/`twitter:card` (hazard image). Sampled metas are unique ✓; confirm OG image per guide for social CTR. | Spot-check `og:image` in the generator HEAD; set to `/assets/wws/<slug>.jpg`. |

## Top 3 fixes to make next
1. **Add JSON-LD structured data** — `LocalBusiness` on the landing + `FAQPage` + `Article`/`BreadcrumbList` on guides. Highest organic-traffic ROI.
2. **Fix guide meta descriptions** — strip HTML + truncate to ~155 chars in `_wws_blog_builder.py` (improves every guide's SERP snippet/CTR at once).
3. **Replace the Tailwind CDN with a built/purged CSS file** — Core Web Vitals + faster paint.
